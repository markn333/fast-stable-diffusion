# BUG-0005: CLIP position_ids が HalfTensor になりモデルロード失敗
- 報告日: 2026-04-29
- ステータス: 完了
- 重要度: 高

## 現象
モデルロード時に `get_empty_cond` の CLIP テキストエンコードでクラッシュ。

```
RuntimeError: Expected tensor for argument #1 'indices' to have one of the following scalar types: Long, Int;
but got torch.cuda.HalfTensor instead
```

エラー箇所:
```
File ".../transformers/models/clip/modeling_clip.py", line 229, in forward
    position_embeddings = self.position_embedding(position_ids)
```

## 原因
BUG-0004 の修正（`assign=True`）により、`sd_disable_initialization.py` がモデルウェイトをチェックポイントから直接割り当てるようになった。その後 `model.half()` が実行される際に、`position_ids`（本来 `Long`/int64 型バッファー）が `HalfTensor`（float16）に変換される。

`torch.nn.Embedding.forward()` は `indices` として `Long` または `Int` 型しか受け付けないため、`HalfTensor` が渡ると RuntimeError が発生する。

## 処置内容
Start セル (`PjzwxTkPSPHf`) に下記 sed パッチを追加:

```bash
!sed -i 's@position_embeddings = self.position_embedding(position_ids)@position_embeddings = self.position_embedding(position_ids.long())@g' \
  /usr/local/lib/{pyver}/dist-packages/transformers/models/clip/modeling_clip.py
```

`position_ids` を `.long()` で明示的に int64 へキャストすることで、dtype に依存せず Embedding への正しい型を保証する。

変更ファイル: `fast_stable_diffusion_AUTOMATIC1111.ipynb`（Start セル）

## 再発防止策
- `assign=True` 使用時は dtype の意図しない変換に注意が必要
- index 系テンソル（`position_ids`, `input_ids` 等）は `.half()` などの全体変換の影響を受けやすいため、Embedding 呼び出し箇所では `.long()` キャストを徹底する
