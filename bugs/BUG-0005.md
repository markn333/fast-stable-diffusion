# BUG-0005: CLIP position_ids becomes HalfTensor, causing model load failure
- Reported: 2026-04-29
- Status: Resolved
- Severity: High

## Symptom
Model loading crashes during CLIP text encoding in `get_empty_cond`.

```
RuntimeError: Expected tensor for argument #1 'indices' to have one of the following scalar types: Long, Int;
but got torch.cuda.HalfTensor instead
```

Error location:
```
File ".../transformers/models/clip/modeling_clip.py", line 229, in forward
    position_embeddings = self.position_embedding(position_ids)
```

## Root Cause
The BUG-0004 fix (`assign=True`) changed `sd_disable_initialization.py` to directly assign model weights from the checkpoint. When `model.half()` is subsequently called, `position_ids` (originally a `Long`/int64 buffer) gets converted to `HalfTensor` (float16).

`torch.nn.Embedding.forward()` only accepts `Long` or `Int` types for indices, so passing a `HalfTensor` raises a RuntimeError.

## Fix
Added the following sed patch to the Start cell (`PjzwxTkPSPHf`):

```bash
!sed -i 's@position_embeddings = self.position_embedding(position_ids)@position_embeddings = self.position_embedding(position_ids.long())@g' \
  /usr/local/lib/{pyver}/dist-packages/transformers/models/clip/modeling_clip.py
```

Explicitly cast `position_ids` to int64 via `.long()`, ensuring the correct dtype for Embedding regardless of any global dtype conversion.

Changed file: `fast_stable_diffusion_AUTOMATIC1111.ipynb` (Start cell)

## Prevention
- When using `assign=True`, be aware of unintended dtype conversions on all tensors
- Index tensors (`position_ids`, `input_ids`, etc.) are susceptible to global dtype conversions like `.half()`. Always cast to `.long()` at Embedding call sites
