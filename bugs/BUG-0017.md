# BUG-0017: `sd_disable_initialization.py` sed forces the slow model-load path, re-downloading ~12 GB every session
- Date: 2026-08-25
- Status: **Reverted by BUG-0020** — correct while Colab shipped transformers 5.x, wrong once transformers was pinned to 4.49.0 (BUG-0019)
- Severity: Medium
- Closes: T-014

## Symptom

Every WebUI start, after the UI is already up:

```
creating model quickly: ValueError
  File "modules/sd_disable_initialization.py", line 68, in CLIPTextModel_from_pretrained
    res = self.CLIPTextModel_from_pretrained(pretrained_model_name_or_path, *model_args,
                                             config=pretrained_model_name_or_path, state_dict={}, **kwargs)
  File "transformers/modeling_utils.py", line 4154, in from_pretrained
    raise ValueError("`state_dict` cannot be passed together with a model name or a `gguf_file`.")

Failed to create model quickly; will retry using slow method.
```

Followed by, on an SDXL checkpoint:

```
model.safetensors:           1.71G   [openai/clip-vit-large-patch14]
open_clip_model.safetensors: 10.2G   [laion CLIP-ViT-bigG-14]
```

Not fatal — the model does load — but roughly **12 GB is fetched on every single session**, and
startup time was measured at 522 s.

## Root Cause

The Start cell carried a `sed` inherited from TheLastBen upstream:

```
res = self.CLIPTextModel_from_pretrained(None   →   res = self.CLIPTextModel_from_pretrained(pretrained_model_name_or_path
```

AUTOMATIC1111's own code (current master, `modules/sd_disable_initialization.py`) is:

```python
def CLIPTextModel_from_pretrained(pretrained_model_name_or_path, *model_args, **kwargs):
    res = self.CLIPTextModel_from_pretrained(None, *model_args,
                                             config=pretrained_model_name_or_path,
                                             state_dict={}, **kwargs)
    res.name_or_path = pretrained_model_name_or_path
    return res
```

Passing `None` as the model name with `config=<name>` and `state_dict={}` is deliberate: it makes
transformers **build the text encoder from its config without fetching any weights**, because the
real weights come from the SD checkpoint moments later. The name is restored on the next line via
`res.name_or_path`, so nothing downstream loses it.

transformers rejects the combination the sed creates — the check is literally:

```python
# transformers/modeling_utils.py
if state_dict is not None and (pretrained_model_name_or_path is not None or gguf_file is not None):
    raise ValueError("`state_dict` cannot be passed together with a model name or a `gguf_file`. ...")
```

With `None` the condition is False and the call is accepted; the sed makes it non-`None`, so it
raises. `modules/sd_models.py` catches that with a broad `except Exception` and falls back:

```python
try:
    with sd_disable_initialization.DisableInitialization(...):
        with sd_disable_initialization.InitializeOnMeta():
            sd_model = instantiate_from_config(sd_config.model, state_dict)
except Exception as e:
    errors.display(e, "creating model quickly", full_traceback=True)

if sd_model is None:
    print('Failed to create model quickly; will retry using slow method.')
    with sd_disable_initialization.InitializeOnMeta():          # <-- no DisableInitialization
        sd_model = instantiate_from_config(sd_config.model, state_dict)
```

The slow path runs **without** `DisableInitialization`, and that context manager is also what
neutralises open_clip:

```python
def create_model_and_transforms_without_pretrained(*args, pretrained=None, **kwargs):
    return self.create_model_and_transforms(*args, pretrained=None, **kwargs)
```

So losing the quick path costs both encoders: 1.71 GB of CLIP-L **and** 10.2 GB of OpenCLIP bigG.
One `sed` on one argument is responsible for the whole 12 GB.

## Fix

`fast_stable_diffusion_AUTOMATIC1111.ipynb`, Start cell — the sed is not merely removed, it is
**reversed**:

```python
!sed -i "s@res = self.CLIPTextModel_from_pretrained(pretrained_model_name_or_path@res = self.CLIPTextModel_from_pretrained(None@" \
  /content/gdrive/$mainpth/sd/stable-diffusion-w$blsaphemy/modules/sd_disable_initialization.py
```

Deleting the line would not have been enough: `sd_disable_initialization.py` lives in Google Drive
and earlier sessions already rewrote it in place, so every existing install still carries the
patched version. The notebook has to undo it actively.

The path was also changed from a hardcoded `/content/gdrive/MyDrive/sd/stable-diffusion-webui/` to
`$mainpth` / `$blsaphemy`, matching every other sed in the cell — the hardcoded form silently
missed Shared Drive users.

### Risk

Low, and bounded: if `from_pretrained(None, config=..., state_dict={})` fails for any reason, the
same broad `except Exception` catches it and the slow path runs — which is exactly today's
behaviour. The worst case of this change is the status quo.

## Changed Files
- `fast_stable_diffusion_AUTOMATIC1111.ipynb` — Start Stable-Diffusion cell

## Prevention

- An upstream patch inherited without a recorded reason is a liability. This one was carried
  forward through every fork of the notebook and cost 12 GB per session once transformers tightened
  its validation. When adopting an upstream `sed`, record what it fixes — otherwise nobody can tell
  later whether it is still needed.
- **A `sed` against a file on Google Drive is persistent state, not a per-session action.** Removing
  the line from the notebook does not restore the file. Any change to such a patch needs the inverse
  operation, or existing installs stay broken forever.
- Prefer `$mainpth` / `$blsaphemy` over hardcoded `/content/gdrive/MyDrive/...`: the hardcoded form
  works for the author and quietly does nothing for Shared Drive users.


---

## Update 2026-08-26: this fix has been reverted

The analysis below holds **only for transformers 5.x**, which is what Colab shipped when it was
written. BUG-0019 pinned transformers to 4.49.0, and under 4.x the picture inverts:

- the 5.x check this record is built on (`state_dict cannot be passed together with a model name`)
  does not exist in 4.x, so passing the name is legal
- 4.49.0 resolves the config from `pretrained_model_name_or_path`, not from `config`, so webui's
  `None` makes it request `https://huggingface.co/None/...` → 401 → the fast path dies anyway

So TheLastBen's sed is the correct form for transformers 4.x, and it has been restored. See
BUG-0020 for the restored version and the reasoning. What survives from this record: the path is
still `$mainpth`/`$blsaphemy` rather than a hardcoded `/content/gdrive/MyDrive/...`, and the
observation that **a sed against a file on Drive is persistent state** — which is why the notebook
can flip this line back and forth at all.
