# BUG-0020: `The shape of the 2D attn_mask is torch.Size([77, 77]), but should be (1, 1)` — open_clip 3.x changed its tensor layout
- Date: 2026-08-26
- Status: Resolved (fix committed, not yet verified on Colab)
- Severity: High

## Symptom

The model gets past construction and weight loading, then dies while computing the empty prompt:

```
loading stable diffusion model: RuntimeError
  File "modules/sd_models.py", line 869, in load_model
    sd_model.cond_stage_model_empty_prompt = get_empty_cond(sd_model)
  ...
  File "sgm/modules/encoders/modules.py", line 470, in encode_with_transformer
    x = self.text_transformer_forward(x, attn_mask=self.model.attn_mask)
  File "open_clip/transformer.py", line 283, in attention
    return self.attn(q_x, k_x, v_x, need_weights=False, attn_mask=attn_mask)[0]
  File "torch/nn/functional.py", line 6515, in multi_head_attention_forward

Stable diffusion model failed to load
```

The BUG-0019 fix is confirmed working in this run: `CLIPTextModel.text_model` no longer raises, and
the traceback now comes from transformers 4.x code paths.

## Root Cause

The notebook installed `open_clip_torch` unpinned, so Colab took **3.3.0**. A1111 pins
`open-clip-torch==2.20.0`.

**open_clip 3.x switched its transformer to `batch_first`.** Counted in the wheels:

| open_clip_torch | `batch_first` references | `permute(1, 0, 2)` references |
|-----------------|--------------------------|-------------------------------|
| 2.20.0 | 0 | 9 |
| 2.24.0 | 0 | 9 |
| **3.3.0** | **36** | 3 |

2.x carries tensors as **LND** (sequence, batch, dim) and permutes explicitly; 3.x carries them as
**NLD** (batch, sequence, dim).

`generative-models` (sgm) was written against 2.x. Its `text_transformer_forward` hands over an
LND tensor with a `[77, 77]` causal mask. Under 3.x's batch-first attention the sequence dimension
lands where the batch dimension is expected, so PyTorch computes `correct_2d_size` as `(1, 1)` — a
single-token sequence — and rejects the `[77, 77]` mask. The number 77 in the error is the CLIP
context length, which is the tell that the axes are transposed rather than the mask being wrong.

## Also in this change: TheLastBen's `sd_disable_initialization` sed is restored

BUG-0017 reversed that sed. **That reversal was right for transformers 5.x and is wrong now that
BUG-0019 pins transformers to 4.49.0**, so it has been put back.

The reasoning, from transformers 4.49.0's own `modeling_utils.py`:

```python
if commit_hash is None:
    if not isinstance(config, PretrainedConfig):
        resolved_config_file = cached_file(
            pretrained_model_name_or_path,      # <-- the model NAME, not `config`
            CONFIG_NAME, ...
        )
```

webui passes `config=<name>` as a **string**, so `isinstance(config, PretrainedConfig)` is False and
transformers resolves the config from `pretrained_model_name_or_path`. With webui's `None` there,
that becomes a request for `https://huggingface.co/None/resolve/main/config.json` → 401 →
`OSError: None is not a local folder and is not a valid model identifier`. The fast path dies and
webui falls back to the slow one, re-downloading CLIP + OpenCLIP (~12 GB) every session.

Passing the real model name fixes it, and transformers 4.x raises no objection to a name alongside
`state_dict={}` — that check (`state_dict cannot be passed together with a model name`) is a 5.x
addition, which is exactly why the sed had to be reversed while Colab was on 5.x.

So the sed is not a mistake by TheLastBen; it is the correct form **for transformers 4.x**, and it
was only ever wrong during the window when Colab shipped 5.x. The notebook now pins 4.49.0, so the
sed belongs. The comment in the cell says so, and says the two are coupled: **if the transformers
pin is ever changed, this sed must be re-evaluated with it.**

## Prevention

- **Every version A1111 pins is pinned for a reason, and the reason is usually that webui reaches
  into that package's internals or feeds it hand-built tensors.** Four bugs in a row now
  (BUG-0016 fastapi, BUG-0019 transformers, this one) have been "the notebook left unpinned what
  webui pinned". The remaining unpinned entries from `requirements_versions.txt` — `kornia==0.6.7`,
  `einops==0.4.1`, `safetensors==0.4.2`, `pytorch_lightning==1.9.4` — are the next candidates if
  something else breaks.
- A shape error naming a familiar constant (77 = CLIP context length) where a `1` is expected is a
  transposed-axes symptom, not a bad-mask symptom. Check the library's tensor layout convention
  before touching the model code.
- **A patch and a pin can be a single decision.** The `sd_disable_initialization` sed is only correct
  for a particular transformers major version; recording that coupling in the cell is what stops the
  next person (or the next session) from flipping one without the other.
