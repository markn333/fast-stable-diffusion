# BUG-0013: Colab base image update (2026-08-24) removed multiple pre-installed packages / broke pytorch_lightning API

- Date: 2026-08-24 – 2026-08-25
- Status: Resolved
- Severity: High
- Consolidates: former BUG-0013 through BUG-0022 (filed individually, merged here since they share one root cause)

## Symptom

A single Colab base image update caused a cascade of failures across multiple startup attempts, each surfacing as a new `ModuleNotFoundError` (or, in one case, an `ImportError` from an API removal) once the previous one was fixed:

| # | Error | Missing/broken import |
|---|-------|------------------------|
| 1 | `ModuleNotFoundError: No module named 'pyngrok'` | tunnel/startup cell |
| 2 | `ModuleNotFoundError: No module named 'pytorch_lightning'` | `ldm` / webui hijack |
| 3 | `ModuleNotFoundError: No module named 'kornia'` | webui image processing |
| 4 | `ModuleNotFoundError: No module named 'open_clip'` | webui CLIP interrogate |
| 5 | `ModuleNotFoundError: No module named 'diskcache'` | webui caching |
| 6 | `ModuleNotFoundError: No module named 'git'` | webui extension manager |
| 7 | `ModuleNotFoundError: No module named 'pytorch_lightning.utilities.distributed'` | `ldm/models/diffusion/ddpm.py` (API removed in pytorch_lightning v2.x, not just missing) |
| 8 | `ModuleNotFoundError: No module named 'piexif'` | webui image metadata |
| 9 | `ModuleNotFoundError: No module named 'pillow_avif'` | webui image format support |
| 10 | `ModuleNotFoundError: No module named 'clip'` | `k_diffusion/evaluation.py` |

While investigating #10, a proactive check of the `k-diffusion` and `sgm` (generative-models) upstream `requirements.txt` files turned up further packages that were missing but had not yet thrown an error (not all code paths that need them had been exercised yet): `clip-anytorch` (the package k-diffusion actually declares, superseding the `openai-clip` used as a first fix), `dctorch`, `invisible-watermark`, `natsort`, `fairscale`, `fire`.

## Root Cause

Colab's base image update on 2026-08-24 removed many previously pre-installed Python packages from the runtime image, and bumped `pytorch_lightning` to v2.x, which removed the `utilities.distributed` submodule (`rank_zero_only` moved to `utilities.rank_zero`). TheLastBen's bundled dependency archive (`gcolabdeps.tar.zst`) is outdated and no longer supplies these packages either, so the notebook has no fallback once Colab stops providing them.

## Fix

Explicitly `pip install` every affected package in the Requirements cell, and apply a `sed` patch for the one true API removal:

```python
# Packages removed from Colab base image (confirmed missing)
!pip install pyngrok pytorch_lightning kornia open_clip_torch diskcache gitpython piexif pillow-avif-plugin -qq

# k-diffusion deps (clip-anytorch supersedes openai-clip; dctorch is k-diffusion specific)
!pip install clip-anytorch dctorch -qq

# sgm (generative-models) deps not in webui requirements.txt
!pip install invisible-watermark natsort fairscale fire -qq

# pytorch_lightning 2.x removed utilities.distributed; rank_zero_only moved to utilities.rank_zero
!sed -i 's@from pytorch_lightning.utilities.distributed import rank_zero_only@from pytorch_lightning.utilities.rank_zero import rank_zero_only@g' \
    /content/gdrive/$mainpth/sd/stablediffusion/ldm/models/diffusion/ddpm.py
```

## Changed Files
- `fast_stable_diffusion_AUTOMATIC1111.ipynb` — Requirements cell

## Prevention

Any package removed from Colab's base image must be explicitly installed in the Requirements cell. When a dependency cascade like this happens, check the upstream `requirements.txt` of all bundled sub-projects (webui, k-diffusion, sgm/generative-models) proactively instead of waiting for each individual `ModuleNotFoundError` to surface one at a time.
