# BUG-0003: Tensor device mismatch error in sd_emphasis.py
- Reported: 2026-04-29
- Status: Resolved
- Severity: High

## Symptom
Model loading fails on AUTOMATIC1111 startup.

```
RuntimeError: Tensor on device cuda:0 is not on the expected device meta!
```

Error location:
```
File ".../modules/sd_emphasis.py", line 42, in after_transformers
    self.z = self.z * self.multipliers.reshape(self.multipliers.shape + (1,)).expand(self.z.shape)
```

## Root Cause
PyTorch 2.10.0 internal dispatch changes cause the multiplication to be executed via `torch._refs` / fake tensor paths. When `self.multipliers` (CPU tensor) and `self.z` (cuda:0 tensor) are on different devices, a meta-device mismatch is triggered.

Specifically, the path `torch._compile` → `torch._dynamo.eval_frame` → `torch._prims` activates a device check against meta tensors.

## Fix
Added the following sed patch to the Start cell (`PjzwxTkPSPHf`):

```bash
!sed -i 's@self\.multipliers\.reshape@self.multipliers.to(device=self.z.device, dtype=self.z.dtype).reshape@g' \
  /content/gdrive/$mainpth/sd/stable-diffusion-w$blsaphemy/modules/sd_emphasis.py
```

Explicitly cast `self.multipliers` to the same device and dtype as `self.z` before the multiplication.

Changed file: `fast_stable_diffusion_AUTOMATIC1111.ipynb` (Start cell)

## Prevention
- On PyTorch major version upgrades, prioritize checking tensor operation code in `sd_emphasis.py` and similar files
- The Environment Check cell is already in place to detect PyTorch version changes
