# BUG-0004: Meta tensor copy error in sd_disable_initialization.py
- Reported: 2026-04-29
- Status: Resolved
- Severity: High

## Symptom
`load_state_dict` fails when switching models from the UI.

```
RuntimeError: Error(s) in loading state_dict for DiffusionEngine:
    While copying the parameter named "...", an exception occurred :
    ('Cannot copy out of meta tensor; no data!',).
```

Error location:
```
File ".../modules/sd_disable_initialization.py", line 221, in load_state_dict
    original(module, state_dict, strict=strict)
```

## Root Cause
PyTorch 2.10.0 `torch.nn.Module.load_state_dict` now explicitly rejects copying values into meta tensors (tensors with no actual data) when `assign=False` (the default behavior).

`sd_disable_initialization.py` uses meta tensors for lazy initialization, and calls `original(module, state_dict, strict=strict)` when loading model weights without passing `assign=True`. This causes copy errors on all parameters.

Passing `assign=True` switches to "direct assignment" mode, bypassing the meta tensor constraint.

## Fix
Added the following sed patch to the Start cell (`PjzwxTkPSPHf`):

```bash
!sed -i 's@original(module, state_dict, strict=strict)@original(module, state_dict, strict=strict, assign=True)@g' \
  /content/gdrive/$mainpth/sd/stable-diffusion-w$blsaphemy/modules/sd_disable_initialization.py
```

Changed file: `fast_stable_diffusion_AUTOMATIC1111.ipynb` (Start cell)

## Prevention
- On PyTorch major version upgrades, verify behavior changes around `load_state_dict`
- `assign=True` is available from PyTorch 2.0+. Backward compatibility with older versions is not required (Colab always uses the latest version)
