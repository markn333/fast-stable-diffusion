# BUG-0012: CLIP position_ids HalfTensor in transformers modeling_clip.py
- Date: 2026-07-25
- Status: Resolved
- Severity: High

## Symptom

AUTOMATIC1111 WebUI starts and reaches the model loading stage, but fails with:

```
RuntimeError: Expected tensor for argument #1 'indices' to have one of the following scalar types: Long, Int; but got torch.cuda.HalfTensor instead (while checking arguments for embedding)
```

Error propagation path:
`sd_models.py:get_empty_cond` → `sd_models_xl.py:get_learned_conditioning` → `sd_hijack_clip.py:encode_with_transformers` → `transformers/models/clip/modeling_clip.py:CLIPTextEmbeddings.forward` → `position_embedding(position_ids)`

## Root Cause

When the SDXL model is loaded in half precision (fp16), all parameters and buffers — including the `position_ids` buffer in `CLIPTextEmbeddings` — are cast to `HalfTensor`. The `torch.nn.Embedding` layer requires `Long` (int64) indices, so passing a `HalfTensor` causes a `RuntimeError`.

This is a recurrence of the same underlying issue as BUG-0005, but occurring in a different location: inside the `transformers` library's `modeling_clip.py` rather than in A1111's `sd_hijack_clip.py`.

## Fix

Added a `sed` patch to the Requirements cell to insert a `.long()` cast at the point of use in `modeling_clip.py`:

```python
!sed -i 's@position_embeddings = self.position_embedding(position_ids)@position_embeddings = self.position_embedding(position_ids.long())@g' \
    /usr/local/lib/python3.12/dist-packages/transformers/models/clip/modeling_clip.py
```

## Changed Files
- `fast_stable_diffusion_AUTOMATIC1111.ipynb` — Requirements cell

## Prevention

Each `transformers` update may reintroduce this issue. The `sed` patch is applied at runtime on every run, so it will automatically reapply after any library update.
