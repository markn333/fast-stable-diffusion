# BUG-0015: Colab moved to Python 3.13 — every hardcoded `python3.12` path silently stopped working, taking pydantic and controlnet_aux with it
- Date: 2026-08-25
- Status: Resolved (fix committed, not yet verified on Colab)
- Severity: High

## Symptom

WebUI dies during UI construction:

```
AttributeError: 'NoneType' object has no attribute '_id'
  File "modules/ui.py", line 489, in create_ui
    toprow.ui_styles.dropdown.change(..., inputs=[toprow.prompt, steps, ...])
```

Preceded by ~20 repetitions of:

```
*** Error creating UI for None:
    File "modules/api/models.py", line 96, in generate_model
      DynamicModel.__config__.allow_population_by_field_name = True
    AttributeError: __config__
```

and one distinct script-load failure:

```
*** Error loading script: controlnet.py
    ModuleNotFoundError: No module named 'controlnet_aux'
```

The model-loading thread then dies with `RuntimeError: cannot schedule new futures after interpreter shutdown`.

## Root Cause

The Colab base image moved from **Python 3.12 to Python 3.13**. Two independent defects in the Requirements cell turned that into a startup failure:

**1. Nine hardcoded `python3.12` paths.** Every `rm` and `sed` in the cell addressed
`/usr/local/lib/python3.12/dist-packages/...` and `/usr/lib/python3.12/...`. On a 3.13 runtime
those paths do not exist, so all nine became no-ops. They run inside
`capture.capture_output()` with `-qq`, so nothing was printed. Among the patches silently
disabled was the BUG-0005/BUG-0012 fix (`position_ids.long()` in `transformers/models/clip/modeling_clip.py`),
which is still needed — the target line exists unchanged in current transformers.

**2. Five packages installed by one pip command.**

```python
!pip install wandb==0.15.12 pydantic==1.10.2 numpy==1.26 scipy==1.15.3 controlnet_aux --no-deps -qq
```

`numpy==1.26` has **no cp313 wheel and no pure-python fallback** (verified on PyPI: `numpy-1.26.4`
ships cp39–cp312 wheels plus an sdist only), so on Python 3.13 pip falls back to building it from
source and fails. pip aborts the *whole* command, so `pydantic`, `controlnet_aux`, `wandb` and
`scipy` were never installed either — again invisibly.

**The failure chain:**

1. `pydantic==1.10.2` not installed → Colab's **pydantic 2.x** stays in place
2. webui's `modules/api/models.py:96` uses the pydantic v1-only API `DynamicModel.__config__` → `AttributeError`
3. `modules/scripts.py:645` (`create_script_ui_inner`) does `import modules.api.models`, so **every** script's UI creation fails; the exception is swallowed at `scripts.py:641` and only printed
4. `ui.py:476` then reads `steps = scripts.scripts_txt2img.script('Sampler').steps` — the Sampler script's UI was never built, so `steps` is `None`
5. gradio's `set_event_trigger` does `[block._id for block in inputs]` on that `None` → **fatal**, webui exits
6. the model-loading background thread is still running, so it dies with `cannot schedule new futures after interpreter shutdown`

`controlnet_aux` missing (same aborted pip command) independently broke `sd-webui-controlnet`'s
`annotator/mobile_sam`. The `WAI-NSFW-illustrious-character-select-EN` error
(`'CharacterSelect' object has no attribute 'steps_component'`) is a downstream symptom of step 3 —
it never saw the steps slider because that UI was never created.

## Fix

`fast_stable_diffusion_AUTOMATIC1111.ipynb`, Requirements cell and Start cell:

1. **Derive the interpreter paths instead of hardcoding them**, so the notebook follows Colab's
   Python version automatically:

   ```python
   pyver   = f"python3.{sys.version_info.minor}"
   sitepkg = sysconfig.get_paths()['purelib']      # /usr/local/lib/pythonX.Y/dist-packages
   if not os.path.isdir(sitepkg):
     sitepkg = f"/usr/local/lib/{pyver}/dist-packages"
   stdlib  = sysconfig.get_paths()['stdlib']       # /usr/lib/pythonX.Y
   ```

   All nine `rm`/`sed` targets now use `$sitepkg` / `$stdlib`, as do the two gradio `blocks.py`
   paths in the Start cell.

2. **One pip install per line**, so one unresolvable pin cannot take the others down:

   ```python
   !pip install pydantic==1.10.22 --no-deps -qq
   !pip install controlnet_aux --no-deps -qq
   !pip install wandb==0.15.12 --no-deps -qq
   !pip install scipy==1.15.3 --no-deps -qq
   ```

   - `pydantic` raised `1.10.2` → **`1.10.22`**: the first 1.10.x with cp313 wheels, and it carries
     the `ForwardRef._evaluate(..., recursive_guard=...)` fix that Python 3.13 requires. webui needs
     the v1 API, so upgrading to pydantic 2.x is not an option.
   - **`numpy==1.26` pin removed.** webui's `requirements_versions.txt` asks for `numpy==1.26.2`, but
     that cannot be installed on Python 3.13 at all. Colab's own numpy is used instead.

3. **Report the outcome instead of hiding it.** After `clear_output()`, the cell now checks the
   packages that must be present and prints the Python version and site-packages path:

   ```
   Python 3.13.x  |  site-packages: /usr/local/lib/python3.13/dist-packages
   ✘ Requirements incomplete - the WebUI will not start:
       - pydantic: 2.11.0 installed, 1.10.x required
       - controlnet_aux: not installed
   ```

## Prevention

- **Never hardcode the Python version in a Colab notebook.** Colab bumps it without notice and the
  resulting failure is silent, because `rm`/`sed` against a non-existent path exit quietly and the
  cell body runs inside `capture.capture_output()`.
- **One `pip install` per line for pinned packages.** A single unsatisfiable pin aborts the whole
  command, and `-qq` inside a capture block makes the loss invisible. The cost of extra lines is
  seconds; the cost of a silent partial install is a cascade like this one.
- **A setup cell that hides its output must state its own result.** Every earlier bug here
  (BUG-0011, BUG-0013, BUG-0014, this one) surfaced as a crash minutes later rather than as an
  install error, which is why they each took a full session to trace.
- Before pinning any version, check that a wheel exists for the runtime's Python version
  (`https://pypi.org/pypi/<pkg>/<ver>/json` → `urls[].filename`). A pin with no matching wheel and
  no pure-python fallback is a build-from-source failure waiting to happen.

## Not Fixed Here (follow-up)

`modules/sd_disable_initialization.py` raises, on every start:

```
ValueError: `state_dict` cannot be passed together with a model name or a `gguf_file`.
```

webui catches this and falls back to the slow path ("Failed to create model quickly; will retry
using slow method"), which works but re-downloads a 1.7 GB CLIP model each session. The cause is
the Start cell's own `sed`:

```
res = self.CLIPTextModel_from_pretrained(None      →      res = self.CLIPTextModel_from_pretrained(pretrained_model_name_or_path
```

which is inherited from TheLastBen upstream. It makes webui pass a model *name* alongside
`state_dict={}`, a combination current transformers rejects. Removing that `sed` is the obvious
candidate fix, but it was added upstream for a reason that is not recorded, so it needs an A/B run
on Colab (with and without) before changing. Tracked as T-014.
