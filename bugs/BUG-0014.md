# BUG-0014: AttributeError: module 'gradio.components' has no attribute 'IOComponent'
- Date: 2026-08-25
- Status: Resolved
- Severity: High

## Symptom

WebUI fails at startup with:

```
AttributeError: module 'gradio.components' has no attribute 'IOComponent'. Did you mean: 'Component'?
```

Error propagation path:
`webui.py` → `initialize.imports()` → `modules/gradio_extensons.py` → `patches.patch(..., obj=gr.components.IOComponent, ...)`

## Root Cause

AUTOMATIC1111 webui's `gradio_extensons.py` patches `gradio.components.IOComponent`, which only exists in Gradio 3.x (webui pins `gradio==3.41.2` in `requirements_versions.txt`). The Requirements cell removes any pre-installed Gradio (`rm -r .../gradio*`) but never reinstalled a pinned version — it relied on whichever Gradio came bundled in `gcolabdeps.tar.zst` or Colab's base image. That bundle/image now provides Gradio 4.x, which renamed `IOComponent` to `Component`, so the patch target no longer exists.

## Fix

Pinned Gradio explicitly in the Requirements cell, matching webui's `requirements_versions.txt`:

```python
!pip install gradio==3.41.2 -qq
```

## Changed Files
- `fast_stable_diffusion_AUTOMATIC1111.ipynb` — Requirements cell

## Prevention

Gradio must be pinned to the exact version webui's `requirements_versions.txt` expects. Removing gradio without reinstalling a pinned version leaves the notebook at the mercy of whatever version happens to be bundled elsewhere.
