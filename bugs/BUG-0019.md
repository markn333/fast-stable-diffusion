# BUG-0019: `'CLIPTextModel' object has no attribute 'text_model'` — Colab ships transformers 5.x, webui needs 4.x
- Date: 2026-08-26
- Status: Resolved (fix committed, not yet verified on Colab)
- Severity: High

## Symptom

The WebUI starts and serves its URL, but **the model never loads**. Two failures in sequence.

First the fast path dies:

```
creating model quickly: AttributeError
  File "modules/sd_disable_initialization.py", line 68, in CLIPTextModel_from_pretrained
    res = self.CLIPTextModel_from_pretrained(None, *model_args, config=..., state_dict={}, **kwargs)
  File "transformers/modeling_utils.py", line 4348, in from_pretrained
    loading_info, disk_offload_index = cls._load_pretrained_model(model, state_dict, checkpoint_files, load_config)
  File "modules/sd_disable_initialization.py", line 74, in transformers_modeling_utils_load_pretrained_model
    return self.transformers_modeling_utils_load_pretrained_model(*args, **kwargs)
  File "transformers/modeling_utils.py", line 4399, in _load_pretrained_model
    hf_quantizer = load_config.hf_quantizer
AttributeError: 'str' object has no attribute 'hf_quantizer'
```

Then the slow path re-downloads 12 GB and dies too — this one is fatal:

```
loading stable diffusion model: AttributeError
  File "modules/sd_hijack.py", line 218, in hijack
    model_embeddings = embedder.transformer.text_model.embeddings
AttributeError: 'CLIPTextModel' object has no attribute 'text_model'

Stable diffusion model failed to load
```

Note the first line of the BUG-0017 fix working as intended: the call now reads
`CLIPTextModel_from_pretrained(None, ...)`, so that sed reversal landed correctly. The remaining
failures are a different problem underneath it.

## Root Cause

**Colab's base image now ships transformers 5.x.** AUTOMATIC1111 webui is built against
transformers 4.x (`requirements_versions.txt` pins `transformers==4.30.2`) and reaches into
internals that v5 restructured. Two separate collisions:

**1. `CLIPTextModel.text_model` is gone (fatal).** `modules/sd_hijack.py:218` does
`embedder.transformer.text_model.embeddings` to install webui's embedding hijack, which is how
textual inversion and prompt handling work at all. transformers 4.x defines
`self.text_model = CLIPTextTransformer(config)` inside `CLIPTextModel`; v5 removed that attribute.
Without the hijack the model cannot finish loading.

**2. webui monkeypatches `_load_pretrained_model` by argument position.**

```python
def transformers_modeling_utils_load_pretrained_model(*args, **kwargs):
    args = args[0:3] + ('/', ) + args[4:]   # resolved_archive_file; must set it to something
    return self.transformers_modeling_utils_load_pretrained_model(*args, **kwargs)
```

It overwrites the 4th positional argument. The signature moved:

| transformers | 4th positional argument |
|--------------|-------------------------|
| 4.30 – **4.49** | `resolved_archive_file` ← what the patch is written for |
| 4.50 – 4.57 | `pretrained_model_name_or_path` |
| 5.x | `load_config` ← overwritten with `'/'`, hence `'str' object has no attribute 'hf_quantizer'` |

## Fix

Pinned `transformers==4.49.0` in the Requirements cell.

**Why 4.49.0 specifically** — it is the newest release satisfying all four constraints, each
verified by unpacking the wheel rather than reading release notes:

| requirement | 4.49.0 |
|-------------|--------|
| `CLIPTextModel.text_model` exists | ✅ `self.text_model = CLIPTextTransformer(` present |
| 4th positional arg is `resolved_archive_file` | ✅ last version where this holds; 4.50.3 / 4.51.3 / 4.52.4 / 4.53.3 all moved it to `pretrained_model_name_or_path` |
| called positionally, so the patch actually lands | ✅ `cls._load_pretrained_model(model, state_dict, loaded_state_dict_keys, resolved_archive_file, pretrained_model_name_or_path, ...)` |
| installable on Python 3.13 | ✅ transformers is pure-python; its `tokenizers<0.22,>=0.21` resolves to a **`cp39-abi3`** wheel, which covers 3.13 |

**Why not A1111's own `transformers==4.30.2`** — it requires `tokenizers>=0.11.1,<0.14`, and
tokenizers 0.13.3 publishes only cp37–cp311 wheels (no abi3). On Python 3.13 pip would have to build
it from Rust sources. The pin is simply not satisfiable on the current Colab image.

Installed **with** dependencies on purpose: transformers 4.x requires `huggingface-hub<1.0`, and
Colab carries hub 1.x for transformers 5. Using `--no-deps` here would leave an incompatible hub in
place and trade one breakage for another.

The BUG-0005 / BUG-0012 `position_ids.long()` sed target was re-checked and is still present in
4.49.0's `models/clip/modeling_clip.py`.

## Expected effect

Both failures should disappear together. Fixing the argument alignment also restores the fast path,
which means `DisableInitialization` stays active and the ~12 GB of CLIP + OpenCLIP downloads that
BUG-0017 was meant to eliminate should finally stop as well — BUG-0017's fix was correct but was
being masked by this.

## Prevention

- **webui pins `transformers` for a reason: it monkeypatches transformers internals by position.**
  Anything the notebook leaves unpinned that webui patches is a break waiting for the next Colab
  image. The same reasoning that produced BUG-0016's fastapi pin applies here.
- When an upstream pin cannot be honoured (4.30.2 is impossible on Python 3.13), do not silently
  fall through to "latest" — find the newest version that still satisfies the *properties* the code
  depends on, and record which properties those were, so the next bump can be checked against the
  same list.
- Argument-position monkeypatches fail silently in the worst way: they do not raise at patch time,
  only much later and inside unrelated code. When one exists, the pinned version is part of the
  patch's contract.
